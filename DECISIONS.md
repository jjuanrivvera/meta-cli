# Decisions

This file pins choices whose alternatives would otherwise make the command surface drift.

1. **Graph version** → default to `v26.0`, released July 29, 2026, and keep it configurable per account and through `META_GRAPH_VERSION` → Meta versions all Graph endpoints and callers need a stable opt-out when migrations take time.
2. **Conservative defaults** → prefer stricter safety behavior when requirements leave room for interpretation → publishing and credential operations should fail closed.
3. **Resource pattern** → service-layer operations declared through one generic command builder → Graph edges, upload phases, field expansions, and publish actions are not uniform CRUD resources.
4. **Enumeration source** → 66 operations transcribed on 2026-09-19 from the public Meta v26 documentation and Meta's public WhatsApp OpenAPI document listed in `specs/enumeration.json` → Pages and Instagram have no complete machine-readable specification.
5. **Composite commands** → list them in the manifest command surface but count only their underlying documented HTTP operations for API completeness → a composite is a convenience workflow, not a new vendor endpoint.
6. **Authentication** → store user token, derived Page token, and optional app secret as separate fields in one encrypted credential record per account; use the Page token for Page operations and the user token for `/me/accounts` → the Graph endpoints require different token types while no credential belongs in configuration or command output.
7. **Profiles** → call them accounts with `--account`; retain hidden `--profile` compatibility → one account groups the business identifiers, Graph version, and credential set.
8. **Pagination** → follow `paging.cursors.after`; never follow an absolute `paging.next` URL → rebuilding through the configured base URL prevents an API response from redirecting credentials to another host.
9. **Rate limiting** → start at 10 requests/second, inspect `X-App-Usage`, `X-Business-Use-Case-Usage`, and `X-Page-Usage`, honor `estimated_time_to_regain_access`, and recognize Graph throttle codes 4, 17, 32, 613, 80000–80009, and 80014 even on HTTP 400/403 → Meta signals throttling through usage telemetry and Graph errors, not only HTTP 429.
10. **Retries** → retry transient network failures, Graph throttles, 429, and 5xx only for idempotent requests; streamed chunks can be reopened and resumable uploads continue from Graph-reported offsets → ordinary Graph POST operations must never duplicate a post or message.
11. **File uploads** → stream only paths explicitly supplied as command flags, never accept file indirection inside API data, and open MCP-selected paths relative to an already-open `META_MCP_ROOT` descriptor with no-follow semantics; unsupported platforms fail closed → this avoids loading large media into memory, closes path-replacement races, and prevents a tool call from becoming an arbitrary local-file read.
12. **Optional local state** → no event store, offline cache, or cross-account sync → publishing is freshness-sensitive and local deterministic fakes are the required test boundary.
13. **Unified surface** → keep Instagram, Pages, and WhatsApp in one binary → operators get one authentication, output, retry, and automation model across Graph API products.
14. **Distribution** → releases are produced only from version tags by the repository workflow → local builds and pull requests cannot publish artifacts accidentally.
15. **Automation integration** → expose the command surface through the built-in MCP server and policy generator → one annotated command tree remains the source of truth.
16. **Toolchain** → declare Go 1.25 with the Go 1.25.12 toolchain → local and CI builds use the same language and standard-library baseline.
17. **Acceptance rubric** → use deterministic behavioral tests for objective criteria → source-code string counts are evidence of presence, not proof of behavior.
18. **Command name** → ship the binary and command-derived runtime identities as `meta` while the repository, Go module, project name, packages, and release archives stay `meta-cli` → the short executable is convenient while packaging retains a distinct, searchable identity.
19. **Environment prefix** → `META_*` for every runtime setting and `META_CLI_VERSION` for the installer's release pin → the installer-specific name avoids confusing a release version with `META_GRAPH_VERSION`; no dependency in `go.mod` or official Meta SDK reads these values implicitly.
20. **Page Video host** → send `/{page-id}/videos` publishing requests to `graph-video.facebook.com` while custom loopback bases remain intact for tests → Meta's Video API publishing guide specifies the dedicated video host, and the Page Videos reference still documents the chunked upload fields.
